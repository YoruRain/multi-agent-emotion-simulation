# 记忆样本构建方法与流程

本文档概述项目中“记忆样本”模块的方法设计、处理流程和输出含义。说明以 `scripts/weibo_analysis/memory_sample/` 目录下的当前实现为准，重点描述如何从用户历史微博、长期情绪画像、主题画像和传播画像中筛选适合 Agent 使用的代表性微博样本。

## 任务目标

记忆样本模块面向后续 Agent 个体化建模，目标是从用户历史微博中挑选少量能够代表用户长期特征的文本。它并不追求覆盖用户全部历史表达，也不简单选择互动量最高或情绪最强的微博，而是在有限条数内兼顾用户的长期关注主题、情绪倾向、语言风格、传播行为和公共议题参与倾向。

该模块位于用户画像与 Agent Prompt 构建之间。上游的长期情绪画像、主题画像和传播画像已经提供了用户级稳定特征；本模块进一步回到微博级文本，从历史记录中选出可直接放入 Agent 上下文的代表样本，使后续 Agent 既有结构化画像，也有贴近用户原始表达的文本参照。

## 输入数据

流程默认读取多类已有结果。微博级输入包括高质量用户微博表、清洗后的用户微博总表、微博级情绪分析结果和微博级主题融合结果。用户级输入包括用户长期情绪画像、最终主题画像、传播画像和用户基础信息表。对于转发微博，流程还会结合清洗后的用户微博总表和源作者信息表，推断转发源作者的大致类型。

微博级主题融合表是主分析入口。它提供微博编号、用户编号、微博正文、是否转发、转发源微博编号、是否带有有效转发评语、最终主题类别、最终主题标签、主题信号来源和主题置信度等信息。微博级情绪结果补充情绪标签、模型置信度、极性得分和情绪强度。高质量用户微博表补充清洗后正文、发布时间、互动量、话题标签和提及用户等元信息。

用户级画像用于解释“这条微博是否能代表这个用户”。长期情绪画像提供主导情绪、强情绪比例、情绪波动和画像可靠性；主题画像提供高频主题类别、高频细主题、公共议题占比、营销内容占比、主题覆盖率和主题可靠性；传播画像提供原创比例、转发比例、带评语转发比例、媒体依赖、KOL 敏感度、互动水平、影响力等级和传播角色。

## 数据预处理

进入筛选前，流程会先做统一的数据整理。用户编号、微博编号和转发源微博编号会被规范为一致的可连接形式，避免数值型和字符串型混用导致合并失败。布尔字段会被统一解释为真或假，文本字段会去除首尾空白，数值字段会转为可计算的数值格式并填补必要的缺失值。

不同来源的数据随后按用户编号和微博编号合并。合并后的基础表同时包含微博自身文本、主题识别结果、情绪识别结果、用户画像特征、互动指标和转发源作者类型。若开启用户数量限制，流程会按用户编号稳定截取一部分用户，便于快速冒烟测试。

对于转发微博，模块不会直接把源微博全文作为用户记忆。若转发微博带有有效评语，则优先提取用户自己的转发评语作为 `content_for_agent`；若没有有效评语，或评语过短、近似占位内容，则不会作为可用文本。原创微博则使用用户自己的清洗后正文。这样可以尽量保证记忆样本体现用户自身表达，而不是把他人内容误当成用户人格记忆。

## 用户分层

模块会先为每个用户划分记忆样本筛选级别，包括核心用户、普通用户和背景用户。

核心用户通常具有更高的建模价值。判断时会综合考虑情绪画像可靠性、主题画像可靠性、是否为核心建模候选用户、传播活跃度、影响力等级、高质量微博数量、公共议题参与比例、带评语转发比例和强情绪表达比例。若用户满足多项条件，会被提升为核心用户。与此同时，营销内容占比会带来扣分，避免广告营销型账号被过度纳入核心记忆构建。

普通用户是默认层级，表示该用户有一定历史微博和画像信息，但不需要像核心用户一样保留较多样本。背景用户通常微博数量较少、画像可靠性不足或主题覆盖较低，这类用户不会强行凑满记忆样本，只在存在高可信文本时保留一条最可靠样本。

这种分层的作用是控制样本预算。核心用户可以获得更丰富的记忆覆盖，普通用户保留少量代表样本，背景用户则避免因数据不足而生成噪声记忆。

## 候选池过滤

候选池过滤负责从合并后的微博表中排除明显不适合进入 Agent 上下文的文本。流程优先保留文本质量达标、长度适中、内容非空、不是低信息文本、不是模板化活动文本、主题和情绪至少有一项较可靠的微博。

低信息文本包括纯转发占位、纯链接、纯话题标签、纯数字、纯符号、仅包含用户名提及或只有简单分隔符的内容。模板化文本主要指抽奖、助力、活动推荐、打榜、签到、点击链接等对用户长期表达价值较低的内容。营销主题也会被排除，防止广告内容进入记忆样本。

长度控制同样重要。过短文本难以体现用户观点或风格，过长文本又不适合直接放入 Prompt。模块会把适合 Agent 使用的文本截取在可控长度内，并在候选过滤阶段保留表达相对完整、信息密度较高的内容。

## 评分设计

通过候选过滤后，每条微博会获得一组可解释的子分数，并据此形成基础记忆分。评分不是单一指标排序，而是多维度衡量一条微博对用户长期记忆的代表性。

质量分主要考虑原始文本质量、进入 Agent 的文本长度和是否为有效内容。理想文本长度会获得更高评价，过短、过长或低信息文本会被降权。

情绪分综合模型置信度、情绪强度和微博情绪方向与用户长期情绪画像的匹配程度。如果用户长期情绪本身较混合或波动较大，流程会允许不同情绪方向的代表样本存在，而不是强行要求所有样本与单一主导情绪一致。

主题分综合最终主题置信度、主题类别或细主题是否命中用户高频关注方向，以及主题信号来自显式主题还是隐式主题。高可信、且落在用户长期高频主题中的微博更容易成为主题代表样本。

公共议题分关注社会公共事件、政策民生和时事政治等类别。如果一条微博属于公共议题，且该用户画像中公共议题占比较高，则会获得更高评价。

传播分主要服务于转发行为记忆。带有效评语的转发微博会获得加分；如果用户整体转发比例、带评语转发比例、媒体依赖或 KOL 敏感度较高，相关样本也会更容易被选中。

互动分对点赞、评论、转发等互动量进行平滑归一化。高互动微博可以辅助体现用户影响力或被关注程度，但它只占较小权重，不会压倒主题、情绪、质量和风格等更核心的记忆维度。

风格分衡量文本是否适合作为用户表达方式的参照。它会结合长度、表达完整度、语气标记、观点性表达、是否为用户本人表达以及噪声水平来评估。完整、有语气、有观点、低噪声的文本更适合作为典型表达样本。

基础记忆分由上述子分数加权得到。当前权重整体上更重视质量、主题和情绪，其次是风格、公共议题、传播行为和互动水平。权重集中在配置中，便于后续根据人工审查结果调整。

## 样本类型

每条入选微博都会被赋予一个 `memory_type`，用于说明它在用户记忆中的主要作用。

`typical_style` 表示典型表达样本，强调日常语言风格、表达完整度和语气特征。`topic_representative` 表示主题代表样本，强调用户长期关注方向。`emotion_representative` 表示情绪代表样本，强调情绪识别可信、情绪强度较高或能体现用户长期情绪倾向。`public_issue` 表示公共议题样本，强调用户对社会公共事件、政策民生或时事政治的参与。`repost_behavior` 表示传播行为样本，强调带评语转发、信息源偏好、媒体依赖或 KOL 敏感。`high_engagement` 表示高互动样本，主要用于补充体现潜在影响力。

如果一条微博同时满足多个类型，流程会按主要建模价值确定类型。公共议题和传播行为通常具有较明确的解释意义，会优先识别；其后再考虑主题代表、情绪代表和高互动特征；若没有更明确的类型，则作为典型表达样本处理。

## 配额选择

用户分层决定了样本数量和类型配额。核心用户默认选择六条，覆盖典型表达、两个主题代表、情绪代表、公共议题和传播行为。普通用户默认选择三条，覆盖典型表达、主题代表和情绪代表；如果该用户明显偏向带评语转发，则普通用户配额会把情绪代表位置替换为传播行为样本。背景用户不设固定多条配额，只在最佳候选达到较高可信度时保留一条。

选择过程以用户为单位进行。对于每个目标类型，流程先在尚未选中的候选中寻找符合该类型条件的微博，并综合基础记忆分、多样性惩罚和该类型对应子分数进行排序。如果某个类型没有合格候选，则退回到综合得分更高的样本，并在选择原因中说明该样本来自配额补位。

每选中一条微博后，流程会从候选池中移除该微博，并重新考虑后续候选与已选样本之间的重复和相似程度。这样可以避免同一用户的多条记忆样本文本高度重复、主题过于集中、情绪方向单一或类型过度重复。

## 多样性控制

多样性控制通过 `diversity_penalty` 体现。若候选文本与已选文本完全相同或高度相似，会被直接跳过；若相似度较高但未达到跳过阈值，则会被降分。若同一用户已经选中了多个相同主题类别、相同情绪方向或相同目标类型，后续同类候选也会受到一定惩罚。

这种机制并不是强制每个用户都覆盖所有维度，而是在尊重用户真实画像的前提下减少冗余。例如，一个高度原创表达型用户可以主要由原创样本组成，但流程仍会尽量避免所有样本都是同一主题、同一语气和同一情绪方向。

## 输出结果

模块默认输出两类结果。

第一类是微博级记忆样本表，默认保存到 `data/profile/weibos/memory_sample/user_weibo_memory_sample.parquet`。该表以用户编号和微博编号为核心，记录用户分层、记忆类型、给 Agent 使用的文本、话题和提及信息、转发源上下文、情绪结果、主题结果、源作者类型、互动分、各项子分数、多样性惩罚、最终记忆分和中文选择原因。

其中，`content_for_agent` 是后续 Prompt 最直接使用的文本。原创微博使用用户自己的内容；带评语转发使用用户自己的转发评语；不适合代表用户表达的源微博全文不会直接进入该字段。`source_context_for_agent` 只保留简短源上下文，例如源作者类型、相关主题和源微博话题，避免把过长外部内容混入用户记忆。

第二类是用户级记忆摘要表，默认保存到 `data/profile/weibos/memory_sample/user_memory_summary.parquet`。该表按用户聚合，记录用户分层、入选样本数量、各类记忆样本数量、入选微博编号列表，以及由高分样本拼接形成的简短 Agent 记忆摘要。该摘要适合作为后续 Prompt 构建的快速入口，也便于人工抽查某个用户的记忆是否合理。

流程还会写入日志，默认位置为 `.log/user_weibo_memory_sample.log`。日志包含用户分层数量、候选微博数量、成功选出样本的用户数、平均每用户样本数、记忆类型分布、原创与转发比例、主题覆盖和情绪标签分布等统计信息。

## 质量校验

保存结果前，流程会进行基础校验。校验内容包括输出字段是否完整、Agent 文本是否为空、同一用户同一微博是否重复、记忆类型是否合法、是否混入广告营销主题、用户样本数量是否超过对应层级配额，以及各项分数是否位于合理范围。

这些校验用于保证输出结果能稳定接入后续 Agent 构建流程。如果候选池为空，流程会给出警告而不是生成不可解释的样本；如果发现结构性问题，则会中止并提示具体异常，便于回到上游数据或配置中定位原因。

## 运行方式

该模块的入口脚本是 `scripts/weibo_analysis/memory_sample/build_user_weibo_memory_sample.py`。在本项目中运行 Python 脚本时，建议使用仓库内的 conda 环境 `D:\GraduationProject\.gp`。

默认运行会读取项目约定路径下的画像和微博数据，生成微博级记忆样本表、用户级记忆摘要表和日志文件。脚本也支持通过参数覆盖输入输出路径、限制用户数量、调整日志路径、关闭用户级摘要输出或开启更详细日志。限制用户数量适合快速检查流程是否能跑通；完整运行则用于生成后续 Agent 建模所需的正式记忆样本。

## 流程概览

完整流程可以概括为八个阶段。

第一，读取微博级主题融合、微博级情绪分析、高质量用户微博、清洗后用户微博、用户基础信息、用户情绪画像、用户主题画像、用户传播画像和源作者信息。

第二，统一编号、布尔值、文本和数值字段，并从用户主题画像中解析高频主题类别和高频细主题。

第三，合并用户级画像并判断用户记忆分层，同时构建转发源作者类型查找表。

第四，以微博级主题融合结果为主表，合并微博元信息、情绪结果、用户画像和源作者类型。

第五，为每条微博生成 Agent 可用文本、话题标签、提及信息和简短源上下文。

第六，过滤低质量、低信息、模板化、营销主题、长度不适合或主题情绪均不可靠的候选微博。

第七，计算质量、情绪、主题、公共议题、传播、互动和风格等子分数，并得到基础记忆分。

第八，按用户分层和类型配额选择样本，在选择过程中加入多样性控制，最后输出微博级样本表、用户级摘要表和日志统计。

## 下游使用建议

在 Agent Prompt 构建中，微博级记忆样本适合与用户级画像摘要搭配使用。用户级画像提供稳定的结构化背景，记忆样本提供贴近原始表达的语料证据。对于核心用户，可以优先使用多条样本构建更完整的个体化上下文；对于普通用户，可以使用少量高分样本补充语言风格和主题偏好；对于背景用户，则应更多依赖用户级画像或群体原型，避免对单条低可靠微博过度解释。

人工审查时，可以重点查看 `memory_type`、`content_for_agent`、`memory_score` 和 `selection_reason`。如果发现样本过于同质、公共议题过少、转发样本过多或风格样本不自然，可以优先调整配置中的配额、阈值和权重，而不需要改动整体流程。
