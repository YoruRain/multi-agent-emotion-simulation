# 评论情绪与立场分析方法与流程

本文档概述项目中“评论情绪与立场分析”模块的方法设计、输入输出结构和批处理流程。说明以 `scripts/comment_analysis/` 目录下的当前实现为准，`docs/prompts/002sentiment_stance_analysis.md` 仅作为任务背景参考。

## 任务目标

评论情绪与立场分析模块面向微博评论文本，目标是把单条评论转化为可用于后续用户画像、Agent 构建和群体情绪模拟的结构化结果。它不仅判断评论表达了什么情绪，也区分评论者相对于某个对象的支持、反对或中立态度，并进一步记录评价焦点、归责对象、可控性感知、规范违背程度、证据片段和复核标记。

该模块强调“情绪”和“立场”的分离：情绪描述评论者的心理状态，例如愤怒、悲伤、喜悦或失望；立场描述评论者面对某个对象、行为、事件、政策或观点时的态度方向。二者可以指向同一对象，也可以在语义上指向不同对象。

## 输入数据

批处理流程默认读取高质量评论数据和话题微博数据。评论数据提供评论编号、微博编号、父评论编号、文本质量标记和评论正文；话题微博数据提供微博编号、话题名称和事件分析上下文。流程会按微博编号把评论和话题上下文关联起来，为模型判断提供话题背景和源微博摘要。

评论筛选遵循两个主要条件：首先根据运行参数选择一级评论或二级评论；其次只保留文本质量标记为高质量的评论。一级评论的父评论文本为空，父评论编号统一视为无父节点；二级评论会尝试根据父评论编号补充被回复评论的正文，作为理解回复关系、指代对象和语境的辅助信息。

每条待分析评论在进入模型前会整理为一个样本，核心信息包括评论编号、微博编号、父评论编号、当前评论正文、父评论正文、话题名称和源微博分析上下文。对于二级评论，当前评论始终是分析对象，父评论只用于辅助理解，不直接继承父评论作者的情绪或立场。

## 分析框架

模块采用三层结构化分析框架。

第一层是情绪事件角色层，关注评论中被情绪指向或被立场评价的对象。该层会识别情绪目标类型、情绪目标文本、立场目标类型、立场目标文本、触发情绪或态度的原因，以及目标对象是否在当前评论文本中被明确提到。

目标类型的当前取值包括事件、人物、机构、群体、社会、政策、媒体、评论者自身、其他评论者、对象、行为和不明确。实现中特别区分行为、政策、事件和对象：行为强调被评价的是做法、操作、处理方式或决策方式；政策强调规则、制度、主张或规范性安排；事件强调具体事件或事件结果；对象则表示具体事物、系统或抽象对象本身。

第二层是评价维度层，关注评论背后的评价结构。该层记录评论的主要评价焦点、主要归责对象、评论者感知到的可控性，以及评论中体现的规范违背或道德谴责程度。评价焦点可以是事件、行为、政策、对象、混合或不明确；归责对象可以是自我、其他个体、机构、媒体、群体、社会、环境或不明确；可控性和规范违背程度均分为高、中、低和不明确。

第三层是任务输出层，给出直接面向建模的结论，包括主导情绪标签、情绪强度、立场标签、立场强度、表达或论证方式和整体置信度。情绪标签的当前取值包括愤怒、悲伤、恐惧、喜悦、厌恶、失望、惊讶、同情、困惑、钦佩、无明显情绪、混合和不明确。立场标签包括支持、反对、中立、混合和不明确。表达或论证方式包括事实陈述、评价、因果说明、反讽、宣泄、诉求、附和、提问和不明确。

情绪强度和立场强度都采用 0 到 3 的等级：0 表示无法判断或基本无明显表达，1 表示弱，2 表示中等，3 表示强。整体置信度使用 0 到 1 的连续数值，用于表示该条分析结果的稳定程度。

## 证据与复核标记

除三层分析结果外，每条评论还会保留情绪证据和立场证据。证据应来自当前评论正文，并尽量使用能够支撑最终判断的最短关键片段。父评论文本和源微博摘要可以帮助理解语境，但不作为当前评论情绪或立场证据的来源。

复核标记用于提示结果是否需要更多上下文，以及在低置信度情况下说明原因。通常，当评论严重依赖省略或代词、目标和立场难以稳定确定、反讽或隐喻存在多种解释、文本过短且缺乏评价锚点时，会被标记为需要更多上下文。若情绪或立场方向已经较清楚，只是对象不够具体，则不一定整体判为不明确。

## 提示词与模型调用

模型调用使用 DeepSeek 兼容的聊天补全接口，默认模型为 `deepseek-chat`。请求中包含系统提示、用户输入和完整的结构化输出要求。系统提示规定分析角色、三层分析任务、情绪与立场区分原则、强度和置信度解释，以及只输出合法 JSON 的要求。

用户输入会把评论编号、话题名称、源微博摘要、父评论摘要、父评论正文和当前评论正文一起提供给模型。对于一级评论，父评论相关内容为空；对于二级评论，父评论信息帮助判断“同意”“反驳”“补充”“讽刺”“质疑”等回复关系。

输出约束会要求模型只返回一个结构化对象，字段名、枚举值和层级必须与当前 Schema 一致。实现中还进一步强调目标抽取、证据抽取、二级评论语境使用、反问与反讽判断、低置信度处理和不明确值的使用边界。

## 结果校验与标签归一化

模型返回内容后，流程会先提取并解析 JSON 对象，再进行标签归一化和结构校验。归一化主要处理模型可能返回的近义但不属于当前枚举的标签。例如，“不认可”类表达不会作为情绪标签保留，而是优先通过反对立场、规范违背程度或评价型表达方式体现；“反讽”会作为表达方式而不是情绪本身；“附和”会作为表达方式，并在必要时补足支持立场。

结构校验会检查返回结果是否符合当前字段结构和枚举范围，并要求返回的评论编号与输入评论编号完全一致。若校验失败，该评论会进入重试流程。成功生成结构化结果后，流程还会做一项语义层面的警告检查：当目标被标记为当前评论文本中明确出现时，目标文本应能在当前评论正文中直接找到。若不满足，会记录语义校验警告，但不会直接丢弃该条结果。

## 批处理流程

一次批处理运行会先加载配置、创建运行编号并初始化日志。随后会归档上一轮失败样本文件，整理已有成功结果，并从 JSONL 和 Parquet 两类成功输出中读取已完成的评论编号。已完成样本会被跳过，失败样本不会被视为完成，因此下次运行会重新尝试。

样本加载完成后，流程根据并发数异步调用模型接口。每条评论有独立的重试机制，请求超时、网络错误、接口错误、返回格式错误或结构校验失败都会触发重试。重试等待时间采用指数退避并加入轻微随机扰动，以降低连续失败时的请求压力。

成功样本会立即追加写入 JSONL 文件，并按配置定期刷新 Parquet checkpoint。失败样本在重试耗尽后写入失败 JSONL，记录评论编号、微博编号、父评论编号、上下文、正文、父评论正文、错误类型、错误信息、重试次数和失败时间。程序结束时会再次从 JSONL 生成或合并 Parquet，保证统计分析使用的扁平表是最新结果。

## 输出结果

成功结果保留两种形态。JSONL 输出保存较完整的嵌套结构，包含原始评论信息、三层分析结果、证据、复核标记、语义校验警告和运行信息。Parquet 输出则把嵌套结构展开为便于统计分析的扁平字段。

扁平输出中的基础字段包括评论编号、微博编号、父评论编号、当前评论正文、父评论正文、源微博分析上下文和话题名称。分析字段包括情绪目标类型、情绪目标文本、立场目标类型、立场目标文本、情绪或态度触发因素、目标是否显式出现、评价焦点、归责对象、可控性、规范违背程度、情绪标签、情绪强度、立场标签、立场强度、表达方式、置信度、情绪证据、立场证据、是否需要更多上下文、低置信度原因和语义校验警告。追踪字段包括模型名称、分析时间和运行编号。

默认成功输出位于 `data/profile/comments/comment_analysis_result.jsonl` 和 `data/profile/comments/comment_analysis_result.parquet`，失败输出位于 `data/profile/comments/comment_analysis_failed.jsonl`，日志默认写入 `.log/comment_analysis.log`。

## 断点续跑与迁移

模块支持断点续跑。启动时会同时读取成功 JSONL 和成功 Parquet 中的评论编号，并把二者的并集作为已完成集合。这样即使某一种输出文件不是最新，也能尽量避免重复调用模型。失败记录不参与跳过判断，目的是让接口波动、临时格式错误或偶发失败的样本在后续运行中仍有机会被重新分析。

目录中还提供了输出迁移流程，用于给历史结果补齐父评论编号和父评论文本。迁移会根据原始评论数据重建评论到父评论的映射，并同步更新成功 JSONL、成功 Parquet 和失败 JSONL。对于一级评论，父评论编号保持为无父节点，父评论文本为空；对于二级评论，会尽量补齐被回复评论正文。

## 在整体项目中的作用

评论情绪与立场分析结果是后续数据建模的重要中间层。一方面，它为评论级统计提供可解释标签，支持观察不同话题下的群体情绪、立场分布、归责模式和规范违背感知；另一方面，它也为用户画像和 Agent 构建提供基础特征，使后续模拟能够把真实评论行为转化为可计算、可追踪的情绪状态和立场倾向。

因此，该模块并不是简单的情感分类器，而是一个面向社会媒体讨论建模的结构化标注流程：它把评论文本、话题上下文和回复关系组合起来，输出兼顾情绪、立场、评价机制、证据和置信度的多维分析结果。
