# 特征工程与数据清洗流程说明

本文根据 `notebooks/03feature_engineering.ipynb`、`notebooks/04-1data_cleaning (comment).ipynb`、`notebooks/04-2data_cleaning (weibo).ipynb` 与 `notebooks/04-3data_cleaning (user_info).ipynb` 整理特征工程和数据清洗流程。说明以自然语言描述各数据结构的处理逻辑，不展开具体实现代码。

## 整体处理顺序

四个 Notebook 之间存在明确的依赖关系：

1. 先从 `data/raw/` 读取四类原始数据，完成基础探索和特征工程，生成 `data/features/` 下的中间特征表。
2. 再清洗话题微博评论数据，生成清洗后的 `topic_comment`。
3. 然后清洗微博数据，其中 `topic_weibo` 会读取清洗后的评论数据，用于统计每条话题微博的评论质量和话题价值；`user_weibo` 则形成用户历史微博的可分析文本集合。
4. 最后清洗用户信息数据，读取清洗后的 `topic_comment` 和 `user_weibo`，把用户在微博和评论中的活跃度、内容质量、原创比例等统计结果回填到 `user_info`。

特征工程阶段的输出统一保存到 `data/features/`，作为清洗阶段输入；清洗后的数据统一保存到 `data/cleaned/`，作为后续高质量样本筛选、用户建模和模拟输入构建的基础。

## 特征工程总览

特征工程 Notebook 的作用是把原始爬取数据整理成更适合清洗和分析的中间结构。它不会进行复杂文本过滤，而是先做数据探索、字段类型整理和基础衍生特征补充，为后续清洗规则提供依据。

在探索阶段，Notebook 会检查四张表的字段、类型、缺失情况、重复记录、文本长度分布和微博特有内容模式，例如链接、话题标签、用户提及、媒体占位和转发关系。它还会特别分析 `user_weibo` 中重复微博 ID 的来源，区分同一用户重复记录和多用户围绕同一微博形成的转发关系。这一观察直接影响后续清洗阶段的去重策略：按微博 ID 和用户 ID 去重，而不是简单按微博 ID 全局去重。

随后，特征工程阶段为微博和评论统一抽取时间维度，包括年份、月份、日期、小时和星期；为文本记录计算原始文本长度；为微博和评论计算互动量；为用户历史微博识别转发状态；为评论统计实际爬取到的子评论数量；为用户信息补充账号年龄和粉丝关注比。处理后的四张特征表被保存为 `topic_weibo`、`topic_comment`、`user_weibo` 和 `user_info`，并成为 04 系列清洗 Notebook 的直接输入。

## 话题微博评论数据：`topic_comment`

### 输入与目标

`topic_comment` 来自特征阶段生成的话题评论数据。该数据结构记录围绕话题微博爬取到的评论，包括评论 ID、微博 ID、父评论 ID、评论用户、评论正文、发布时间、点赞数、子评论数量、IP 属地等信息。

清洗目标是保留评论中的真实表达和情绪线索，同时剔除会干扰情绪分析的网页标记、链接、回复前缀和低信息内容，并为每条评论标注文本质量等级。

### 特征工程衔接

在进入清洗之前，特征工程阶段已经为评论表补充了时间特征、原始文本长度和互动量。评论互动量由点赞数和原始子评论数共同构成，用来描述评论本身受到的反馈强度。

特征工程还会根据父评论关系统计每条评论在当前数据集中实际拥有多少条被爬取到的子评论。这个字段与平台展示的子评论数不同，更强调本地数据集里真实可用的二级评论规模。与此同时，评论文本质量会先被初始化为“可分析”，后续清洗阶段再根据空文本、占位内容、纯符号、寒暄互动等规则进行细分修正。

### 文本清洗流程

评论正文会先经过基础文本规范化。流程上先去除 HTML 标签和外部链接，再处理评论区常见的“回复某用户”前缀，只保留真正的回复正文。随后将连续空白、换行和制表符压缩成统一空格，并去掉首尾空白。

该阶段不会删除话题标签中的文字内容，也不会对正常中文表达做激进过滤，目的是尽量保留评论中的态度、情绪、评价对象和互动语气。

### 文本质量分级

清洗后，评论会被划分为五级文本质量。实际规则中主要使用 0 到 3 级，4 级预留给后续扩展。

- Level 0 表示空文本，包括空字符串、纯空白或清洗后没有有效内容的评论。
- Level 1 表示极低信息文本，例如模板转发、图片评论占位、纯数字、纯符号、纯英文、纯表情或只包含用户提及的内容。
- Level 2 表示低分析价值文本，主要包括寒暄问候、简单附和、礼貌感谢、签到打卡、接好运等仪式性互动。这类内容是用户真实表达，但对情绪和立场分析帮助较弱。
- Level 3 表示可分析文本，通常包含明确语义、态度、情绪或事件相关评价。
- Level 4 在当前 Notebook 中没有主动识别，保留为未来更高质量文本筛选的扩展等级。

分级完成后，数据中会增加文本质量数值和对应的中文标签。后续流程通常将 Level 3 及以上视为高质量或可分析评论。

### 输出结果

清洗后的 `topic_comment` 保留原有评论结构，并补充评论质量字段。该数据一方面用于描述评论区整体质量，另一方面会被微博清洗流程读取，用于按微博聚合评论数量、高质量评论数量、高质量评论用户数和高质量评论比例。

## 用户历史微博数据：`user_weibo`

### 输入与目标

`user_weibo` 来自特征阶段生成的用户历史微博数据，记录用户过往发布或转发的微博内容、发布时间、互动数、是否转发、转发源微博 ID、话题和提及用户等信息。

清洗目标是把用户历史微博转化为可用于用户画像和长期表达建模的文本集合，同时过滤系统提示、活动营销、抽奖模板、占位内容和低信息互动。

### 特征工程衔接

特征工程阶段会先为用户历史微博补充时间特征、原始文本长度和互动量。互动量由点赞数、评论数和转发数合成，用来衡量单条微博的传播反馈。

该阶段还会根据转发源微博 ID 判断每条记录是否为转发，并保留转发源关系。这个转发标记随后用于用户信息清洗阶段计算原创比例，也用于清洗阶段解释为什么同一微博 ID 可能出现在不同用户记录中。用户历史微博的文本质量同样会先被初始化为“可分析”，后续再由清洗阶段识别系统提示、活动模板、占位内容和低信息文本。

### 去重流程

用户历史微博首先按微博 ID 和用户 ID 进行去重。这样可以删除同一用户重复出现的同一条微博，同时保留不同用户围绕同一微博形成的转发关系。该策略避免误删跨用户传播链路，也减少同一用户重复记录对用户画像统计的影响。

### 文本清洗流程

微博正文会保留原始内容，并额外生成清洗后的正文。清洗过程先去除网页标记和链接，再移除微博平台常见的媒体占位内容，例如视频、图片、音乐、文章或直播占位。随后删除用户提及和话题标签，并统一空白格式。

与评论数据不同，用户历史微博的清洗会主动去掉话题标签和用户提及，因为该结构更关注用户自身表达内容，而不是平台附加标记或传播包装。

清洗后会计算清洗文本长度，用于后续文本质量判断和数据概览。

### 文本质量分级

用户历史微博默认被视为普通内容，然后根据规则下调到低质量或无效类别。

- Level 0 表示系统提示或空内容。系统提示包括微博被删除、权限受限、账号异常、内容违规、被投诉侵权等平台生成文本；空内容则表示清洗后没有有效表达。
- Level 1 表示广告、抽奖、营销或平台活动模板，例如红包、抽奖、优惠、签到、会员活动、福利互动、转发关注类内容，以及纯话题占位或功能性转发文本。
- Level 2 表示低信息量文本，例如简单参与互动、固定祝福、纯感叹、纯表情、纯数字、纯符号、纯英文、纯用户提及等。
- Level 3 表示普通内容，具备基本语义，可用于后续情绪或用户画像分析。
- Level 4 在当前流程中作为未来扩展等级保留。

分级结果会以数值等级和中文标签写回数据表。后续用户信息清洗会读取这些等级，统计每个用户的高质量微博数量和高质量微博比例。

### 字段整理与输出

输出前会调整字段顺序，使数据按 ID 与用户、文本、文本质量、时间、互动、转发关系和社交原数据组织。最终保存为清洗后的 `user_weibo`，供用户活跃度统计、内容质量统计和用户价值分类使用。

## 话题微博数据：`topic_weibo`

### 输入与目标

`topic_weibo` 记录进入话题分析范围的微博，包括微博 ID、发布用户、话题、正文、发布时间、互动数、热搜日期、热搜类型和热搜点击量等信息。

清洗目标有两个：一是得到规范化的微博正文；二是结合评论质量统计，判断每条话题微博是否适合作为后续事件分析和模拟输入候选。

### 特征工程衔接

特征工程阶段会先为话题微博补充时间特征、原始文本长度和互动量。互动量由点赞数、评论数和转发数合成，用于描述话题微博在平台上的整体反馈强度。

这一阶段还会保留热搜词条相关信息，包括热搜日期、热搜类型和热搜点击量。后续清洗阶段在进行话题价值评估时，会继续使用这些热搜信息，尤其是热搜类型信息，用来辅助区分具有更高建模价值的话题微博。

### 去重与文本清洗

话题微博同样按微博 ID 和用户 ID 去重，以删除重复记录并保留必要的跨用户关系。文本清洗流程与用户历史微博一致：保留原始正文，新增清洗正文，去除网页标记、链接、媒体占位、用户提及、话题标签和多余空白。

### 评论质量聚合

在清洗话题微博时，会读取已经清洗好的 `topic_comment`，按微博 ID 聚合评论侧信息。聚合结果包括：

- 当前微博实际爬取到的评论总数。
- 文本质量达到可分析标准的评论数量。
- 高质量评论在全部爬取评论中的比例。
- 发布高质量评论的去重用户数量。

如果某条话题微博没有匹配到评论记录，这些统计字段会被填充为零，避免后续计算出现缺失值。

### 话题价值评估

话题价值分类基于评论侧统计和热搜信息共同完成。流程会先在当前数据集中计算高质量评论数量和高质量评论用户数的分位阈值，再根据每条微博相对位置划分价值等级。

评论质量和高质量评论用户数处于较低区间的微博会被标记为相对低价值；拥有较多高质量评论、较多高质量评论用户，并且具备热搜类型信息的微博会被标记为相对高价值；其余微博归为一般价值。

这一分类的含义不是判断微博内容本身“好坏”，而是评估它是否拥有足够评论样本和讨论密度，能否支撑后续事件建模、评论分析和模拟实验。

### 字段整理与输出

输出前，话题微博字段会按用户与话题、文本、时间、互动、评论聚合统计、话题价值评估和热搜信息重新排列。最终保存为清洗后的 `topic_weibo`。

## 用户信息数据：`user_info`

### 输入与目标

`user_info` 来自特征阶段生成的用户基础信息，包含用户 ID、昵称、性别、IP 属地、注册时间、账号年龄、认证信息、粉丝数、关注数、粉丝关注比、用户等级和个人简介等字段。

清洗目标是把静态账号信息与用户在微博、评论中的实际行为结合起来，形成可用于用户筛选、画像构建和 Agent 建模的用户价值数据结构。

### 特征工程衔接

特征工程阶段会先统一用户 ID 类型，规范注册时间，并基于固定参考日期计算账号年龄。无法解析注册时间的记录会得到特殊的账号年龄占位值，以便后续流程识别缺失或异常注册信息。

用户 IP 属地中的未知值和空字符串会被转为缺失值，避免把“未知”误当作真实地理位置。特征工程还会计算粉丝关注比，用于补充账号影响力和社交结构信息。清洗阶段在此基础上继续回填微博、评论和活跃度统计，并完成用户价值分类。

### 用户行为统计回填

该流程会读取清洗后的 `user_weibo` 和 `topic_comment`，按用户 ID 汇总行为统计。

微博侧统计包括用户被爬取到的微博数量、高质量微博数量、高质量微博比例、原创比例和 2025 年微博数量。原创比例用于衡量用户表达中原创内容相对于转发内容的占比。

评论侧统计包括用户被爬取到的评论数量、高质量评论数量和高质量评论比例。

活跃度统计会分别从微博发布时间和评论发布时间中计算用户活跃天数，并取两者中的较大值作为用户总体活跃天数。这样可以覆盖只发微博、只评论或两类行为都存在的用户。

统计结果回填后，缺失的数量类字段会被补为 0，比例类字段会被补为 0.0，并统一为适合后续分析的数值格式。

### 个人简介清洗

用户简介会进行轻量文本清洗，去除网页标记、链接和多余空白。清洗后为空的简介会被视为缺失值，而不是保留空字符串。该处理可以减少后续画像生成时的无意义输入。

### 用户价值分类

用户价值分类用于区分不同用户是否适合进入后续建模样本。分类前会根据当前用户集合计算多个分位阈值，包括微博爬取数量、高质量微博数量、高质量微博比例、2025 年微博数量、活跃天数和高质量评论数量等。

分类逻辑按优先级判断：

- 非普通个体用户：认证类型不属于普通用户或个人认证的账号会单独归类，避免机构、媒体、组织号和其他非个人账号混入个体用户建模。
- 低可用用户：微博数量、高质量微博数量、活跃天数或高质量评论数量处于较低区间的用户会被归为低可用。
- 核心建模候选用户：微博数量、高质量微博数量、高质量微博比例、近期微博数量、活跃天数和高质量评论数量均达到较高区间的用户会被归为核心候选。
- 高可用用户：多项核心指标达到中位数以上，但未满足核心候选严格标准的用户会被归为高可用。
- 一般可用用户：不属于以上类别但仍具备一定数据基础的用户会被归为一般可用。

该分类强调用户是否拥有足够稳定、近期、可分析的表达样本，而不是简单以粉丝数或认证状态衡量用户重要性。

### 字段整理与输出

最终 `user_info` 会按基础身份、地理位置、账号信息、社交指标、微博内容统计、评论内容统计、活跃度、个人简介和用户价值分类组织字段，并保存为清洗后的 `user_info`。

## 特征工程与清洗后数据之间的关系

完整流程形成了一个逐层增强的数据链路：

- `data/raw/` 中的原始表先进入特征工程阶段，统一时间、长度、互动、转发、子评论、账号年龄和社交比例等基础特征。
- `topic_comment` 提供评论级文本质量，是话题微博价值评估的基础。
- `topic_weibo` 在原始微博信息上补充评论质量聚合结果，用于筛选适合建模的话题事件。
- `user_weibo` 提供用户历史表达质量，是用户画像和长期行为统计的基础。
- `user_info` 汇总用户静态属性、微博行为、评论行为和活跃度，并给出用户建模价值等级。

因此，03 和 04 系列 Notebook 并不是彼此独立的处理脚本，而是从原始爬取数据到中间特征表，再到清洗后分析数据的连续管线。特征工程阶段决定了清洗阶段可以依赖哪些基础字段；清洗阶段的文本质量判断又会继续影响后续的话题价值和用户价值评估。
