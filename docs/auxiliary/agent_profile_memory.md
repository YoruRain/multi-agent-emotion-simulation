# Agent 画像与记忆构建方法与流程

本文档概述 `scripts/agent_data_preparation/` 目录中与 Agent 画像和记忆构建相关的处理流程。说明聚焦用户画像数据融合、智能体基础画像表示、智能体系统提示词构建和智能体记忆样本构建四项工作，不展开具体代码实现。

## 任务目标

Agent 数据准备模块位于用户画像分析结果和群体仿真系统之间。上游的长期情绪画像、主题画像、传播画像和记忆样本分析已经分别从不同角度描述了微博用户的长期特征，但这些结果仍分散在多个数据表中，不能直接作为模拟系统中的 Agent 输入。

本模块的目标是把这些分散结果整理为一组稳定、统一、可被模拟器读取的 Agent 输入数据。它既保留用户的结构化行为参数，也生成适合放入系统提示词的自然语言摘要，还把代表性历史微博整理为 Agent 记忆。经过该模块处理后，每个微博用户可以被表示为一个具有身份背景、情绪倾向、主题兴趣、传播习惯和历史表达样本的 Agent。

## 数据来源与总体链路

流程默认接收五类上游数据。

第一类是用户基础信息，主要描述用户编号、昵称、性别、认证状态、简介、用户价值等级等基础属性。它决定最终 Agent 覆盖的用户集合，也是后续多表融合的主干。

第二类是长期情绪画像，提供用户积极、中性、消极表达比例，平均极性，情绪波动，平均强度，强情绪比例，以及面向人工理解的情绪画像摘要。

第三类是主题画像，描述用户长期关注的主题结构，包括公共议题、娱乐内容、日常生活等主题占比，转发源主题依赖程度，以及用户主题兴趣摘要。

第四类是传播画像，刻画用户粉丝规模、传播活跃度、原创与转发习惯、媒体依赖、KOL 敏感度、影响力等级和传播角色，并提供对应的传播行为摘要。

第五类是记忆样本相关结果，包括用户分层、入选历史微博数量、样本类型分布、被选中的微博编号，以及可直接面向 Agent 使用的记忆摘要或微博样本文本。

整体链路可以理解为三步。首先，模块把多个画像结果按用户编号合并，形成统一的 Agent 基础画像。随后，它从基础画像中提炼系统提示词所需的身份、情绪、主题和传播摘要。最后，它将代表性历史微博按用户聚合为 Agent 记忆，使后续模拟既能使用结构化参数，也能参考用户过去的真实表达。

## 用户画像数据融合

画像融合以用户基础信息为主表，逐步连接情绪画像、主题画像、传播画像和记忆摘要。这样设计的好处是可以保证 Agent 集合由明确的用户基础表控制，同时允许部分画像数据缺失。某个用户如果暂时缺少某类画像，流程不会直接丢弃该用户，而是在对应位置使用默认说明或空值补齐。

在融合前，各输入表会进行基础整理。用户编号会被统一为稳定的字符串形式，避免同一编号因为数值型、浮点型或字符串型差异而连接失败。缺失字段会被补齐，重复用户会保留一条稳定记录，数值、布尔、列表和字典类字段也会被转换为后续更容易使用的形式。

融合过程中，模块会记录每类画像在用户集合中的缺失情况。这一信息有助于判断上游画像覆盖是否充分，也能提醒后续分析者：某些 Agent 的行为可能更多依赖基础身份和默认描述，而不是完整的长期画像。

融合后的结果不只是简单拼接字段，而是会进一步整理为适合 Agent 使用的表示。用户的认证状态、粉丝规模、活跃程度和传播角色会组合成身份摘要；情绪、主题和传播画像中已经生成的中文摘要会被保留为提示词材料；多个连续指标会统一放入行为参数区域，供模拟阶段进行规则判断或概率计算。

## 智能体基础画像表示

基础画像的核心作用，是把一个微博用户转化为模拟系统中的 Agent。每条画像记录都包含可追踪的用户编号和 Agent 编号，同时划分为基础身份、提示词画像、行为参数和元数据四个部分。

基础身份部分描述用户的相对稳定属性，例如昵称、性别、认证类型、用户价值等级、粉丝规模、影响力等级、传播角色和记忆分层。这些信息用于回答“这个 Agent 是什么样的微博用户”，也为后续用户分层和模拟结果解释提供直观依据。

提示词画像部分面向语言模型或规则化反应生成。它不直接堆叠原始字段，而是保留四段可读摘要：身份背景、长期情绪倾向、主题兴趣和传播行为。这样的表示更接近人类对用户特征的理解，也避免系统提示词中出现大量零散、难以解释的指标。

行为参数部分保留连续数值特征，例如情绪比例、平均极性、情绪强度、主题占比、转发比例、媒体依赖、KOL 敏感度和影响力分数等。这些参数适合在仿真中参与可计算的规则，例如判断用户是否更可能参与公共议题讨论、是否更偏向转发扩散、是否更容易表现出强情绪反应。

元数据部分记录记忆样本的覆盖情况，例如用户拥有多少条入选记忆、各类记忆的大致分布，以及被选中的历史微博编号。这些信息不一定直接决定 Agent 输出，但能够帮助检查一个 Agent 的历史依据是否充足。

通过这种分层表示，基础画像同时服务于三类需求：给人阅读时足够清晰，给提示词生成时足够自然，给模拟程序使用时又保留可计算参数。

## 智能体系统提示词构建

系统提示词构建以 Agent 基础画像为输入，将其中的提示词画像转化为一段完整的角色设定。它的任务不是重新分析用户，而是把已经形成的身份、情绪、主题和传播摘要组织成适合 Agent 扮演的说明。

提示词首先明确 Agent 的角色：它正在扮演一个微博用户，需要根据该用户长期画像、主题兴趣、传播习惯和代表性记忆，对热点事件或微博语境做出符合用户特征的反应。随后，提示词按基础身份、长期情绪倾向、主题兴趣和传播行为四个维度依次呈现用户背景。

这类提示词强调两个约束。第一，Agent 不应默认每次都参与讨论，而是需要根据自身画像判断是否参与。如果用户对事件兴趣较低，或画像可靠性不足，可以选择低强度反应或不参与。第二，Agent 的表达应符合用户的情绪倾向、主题偏好和传播习惯，但不能机械复述画像字段，也不能在输出中提到数据集、画像或模型等元信息。

提示词还规定了后续反应结果的结构化输出要求。模拟系统需要知道 Agent 是否参与、采取何种动作、表达何种情绪和立场、反应强度如何，以及给出怎样的微博式文本。因此，系统提示词会把这些输出约束一并写入，使语言模型生成结果时更容易被程序解析和校验。

如果某个用户缺少部分画像摘要，提示词会使用默认的“暂无相关画像信息”类说明补足，而不是让提示词结构断裂。这样可以保证所有 Agent 都拥有一致的提示词格式，方便批量运行和结果比较。

## 智能体记忆样本构建

记忆样本构建面向用户历史微博样本。它的目标是为每个 Agent 提供少量有代表性的历史表达，使 Agent 不只依赖抽象画像，也能参考用户过去真实发布或转发时的语言风格、主题偏好和传播行为。

输入样本来自上游记忆筛选流程，已经包含用户编号、微博编号、用户记忆层级、记忆类型、面向 Agent 的正文、主题标签、提及信息、转发源背景、情绪标签、最终主题类别、来源类型、互动或筛选得分，以及样本入选原因等信息。本模块会在此基础上做统一整理，并按用户聚合。

整理阶段会统一用户编号和微博编号，过滤掉无法归属到用户的记录，并把记忆分数、是否转发、是否带转发评论等字段转换为稳定格式。缺失字段会被补齐为默认值，避免部分样本因为上游字段不完整而中断整批构建。

记忆样本会被进一步标记为不同用途。能够体现语言表达方式的样本会被视为风格记忆；属于社会公共事件、政策民生或时事政治等类别的样本会被视为公共议题记忆；转发行为相关样本会被视为传播记忆；其余可用样本则作为一般记忆。这样的标记有助于后续理解一条历史微博为什么被放入 Agent 上下文。

记忆内容本身会被整理成适合提示或上下文使用的自然语言片段。模块会说明这条历史微博是原创、转发附评还是纯转发，标注其主要主题和情绪，并保留用户自己的可用表达。对于存在转发源背景的样本，还会附带源微博背景，使 Agent 能区分用户自己的表达与其接触到的信息来源。

不同层级用户拥有不同的记忆预算。核心用户会保留更多历史样本，普通用户保留少量代表样本，背景用户只保留最少样本。模块会在每个用户内部按记忆分数排序，并根据用户层级截取最有代表性的记录。这样既控制了 Agent 上下文长度，也避免低可靠用户被强行填充过多噪声记忆。

最终，每个 Agent 会得到一组按用户聚合的记忆记录。每条记忆既包含可直接使用的文本片段，也保留主题、提及、样本类型、情绪标签、主题来源、源作者类型和筛选原因等元信息。模拟或人工检查时，可以同时看到“Agent 记住了什么”和“这条记忆为什么被选中”。

## 输出结果与下游用途

该目录最终面向模拟系统生成三类核心输入。

第一类是 Agent 基础画像。它以用户为单位，将基础身份、提示词摘要、行为参数和记忆元信息组织成统一记录，是后续单事件模拟和多轮模拟读取用户特征的主要入口。

第二类是 Agent 系统提示词。它把结构化画像转化为可直接用于 Agent 扮演的角色说明，并约束 Agent 在事件反应中的参与判断、动作类型、情绪、立场和输出格式。

第三类是 Agent 记忆。它将代表性历史微博按用户聚合，为 Agent 提供具体的表达样本、主题记忆、公共议题参与痕迹和传播行为参照。

这三类结果共同完成了从“用户画像分析结果”到“可运行 Agent 输入”的转换。基础画像提供稳定特征，系统提示词提供角色设定，记忆样本提供历史表达依据。后续模拟阶段可以在此基础上生成更具个体差异的微博用户反应，并在结果分析时追溯每个 Agent 的行为来源。

## 运行与检查要点

使用该模块时，应先确保上游情绪画像、主题画像、传播画像和记忆样本结果已经生成，并且用户编号能够彼此对齐。若某一类画像缺失，流程仍可生成输出，但对应 Agent 的个性化程度会下降。

完成构建后，建议检查三类结果的用户数量是否一致，抽查若干 Agent 的身份摘要、情绪摘要、主题摘要和传播摘要是否符合上游画像，并确认记忆样本文本主要体现用户自身表达，而不是误把转发源内容当作用户观点。

对于后续仿真而言，还应重点关注核心用户和普通用户的记忆覆盖情况。如果核心用户缺少记忆样本，或大量用户只拥有默认提示词说明，说明上游记忆筛选或画像覆盖可能需要重新检查。
